# LinkedIn Build-in-Public Plan

## Goal

Use the project as a transparent record of problem-solving, research, engineering and measurable results.

## Do not post

- "Day 1 of my AI project"
- Generic AI-generated motivational content
- Unverified claims such as "I built a production-ready CFO AI"
- Screenshots without explaining the underlying problem or result

## Post instead

### Research findings

"I reviewed existing cash-flow forecasting products. Forecasting itself is mature, so I changed the project from forecasting to independent forecast reliability and stress testing."

### Engineering decisions

"I chose time-based backtesting instead of random train/test splits because future financial data must not leak into historical predictions."

### Finance insights

"A forecast can have a good average error while still being systematically optimistic. Here is how we measure forecast bias."

### Experiments

"Baseline MAE: X days. New approach: Y days. Improvement: Z%. Here is the trade-off."

### Failure cases

"Our model failed when customer history was sparse. Instead of hiding it, we added a data-sufficiency gate."

### Product milestones

Show the application evolving from data upload to validation, backtesting, stress testing and explainable reports.

## Recommended cadence

Aim for 2–4 substantive posts per week. Daily posting is optional; daily low-value updates are not the goal.

## Every post should contain

1. The problem or question.
2. What was tested or built.
3. Evidence, screenshot, metric or code-level decision.
4. What was learned.
5. The next hypothesis or experiment.
